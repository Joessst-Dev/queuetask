Step {{.Idx}}
{{/* ── Identity ── */}}

Unique identifier used in depends_on references and API calls. No spaces or special characters.

manual — waits for an explicit API call to advance it. auto — completes immediately when dependencies finish. queueti — waits for a message on a queue-ti topic. http — makes an outbound HTTP request and completes with the response.

Human-readable summary shown in the canvas UI. Not used at runtime.

Comma-separated names of steps that must complete before this step becomes active. Leave empty to start immediately when the workflow starts.

Optional. When this step completes, its output is published to this queue-ti topic. Useful for notifying other services or workflows.

{{/* ── queueti-only fields ── */}}

The queue-ti topic this step subscribes to. The step completes when the first message arrives, with the message payload as its output.

Consumer group name used when reading from the topic. Defaults to queuetask if left empty.

{{/* ── http-only fields ── */}}

Full URL of the endpoint to call. Must use https:// or http://. Private/loopback IP ranges are blocked. The step's input is sent as the JSON request body and the response body becomes the step output.

Defaults to POST. GET and HEAD requests do not send a body.

Trigger {{.Idx}}

cron — starts a new instance on a schedule. webhook — starts a new instance when POST /api/v1/workflows/{name}/webhook is called; the request body becomes the instance input. queueti — starts a new instance for each message received on a queue-ti topic.

{{/* ── cron-only fields ── */}}

Standard 5-field cron expression (minute, hour, day-of-month, month, day-of-week). Example: 0 9 * * 1-5 fires at 09:00 on weekdays.

Optional JSON passed as the instance input each time this cron fires. Useful for providing configuration that the workflow's first steps can read. Must be valid JSON if provided.

{{/* ── queueti-only fields ── */}}

The queue-ti topic to subscribe to. Each incoming message starts a new workflow instance with the message payload as the instance input.

Consumer group name for reading from the topic. Use a unique name per workflow so each workflow processes every message independently.
